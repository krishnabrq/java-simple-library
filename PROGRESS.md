# Progress

## Done

- Scaffolded via start.spring.io: web-mvc, data-jpa, h2, devtools, validation. Java 25, Gradle, Spring Boot 4.0.6.
- API mounted at `/api/v1/books` (class-level `@RequestMapping`).
- Package-by-feature; `common/` created only when first cross-cutting class arrived. `config/`, `storage/`, `messaging/` deferred.
- JPA + H2 in-memory + console + SQL logging. `BookEntity` (class, not record — JPA needs no-arg ctor + mutability). No `setId`.
- CRUD on `/api/v1/books`: GET list, GET by-id (404 via `BookNotFoundException`), POST (201), PUT (full replace), PATCH (partial via `PatchRequest` with nullable wrapper types), DELETE (204; 404 if missing).
- `common/GlobalExceptionHandler` (`@RestControllerAdvice`). Handles: `BookNotFoundException` (404), `NoResourceFoundException` (404, replaces Whitelabel HTML), `MethodArgumentNotValidException` (400, body validation field errors), `HandlerMethodValidationException` (400, param-level validation), `MethodArgumentTypeMismatchException` (400, path/query conversion), `HttpMessageNotReadableException` (400, malformed JSON).
- `spring-boot-starter-validation`. `WriteRequest` (POST/PUT): `@NotBlank @Size(1,1000)` title, `@NotNull @PositiveOrZero @Max(100_000)` count. `PatchRequest` (PATCH): null-tolerant only (`@Size`, `@PositiveOrZero`, `@Max`). `@Min(1)` on `bookId` path variables.
- `common/ErrorResponse` record (preserves component order in JSON; vs `Map.of` unordered).
- `BookService`: extracted from controller. Class-level `@Transactional(readOnly = true)`; method-level `@Transactional` on writes.
- `BookDto.Response` record. Controller returns DTOs only; entity stays internal.
- `BookMapper` (MapStruct, `componentModel = "spring"`): `toResponse`, `toResponses`, `toEntity` (`@Mapping(target="id", ignore=true)`), `updateFromWriteRequest` (PUT), `updatePatch` (PATCH; `@BeanMapping(nullValuePropertyMappingStrategy = IGNORE)`).
- `AGENTS.md` canonical; `CLAUDE.md` shrunk to pointer.

- `Makefile`: `help`, `build`, `run`, `test`, `clean`, `compile`, `watch`, `deps`, `format`, `format-check`. Self-documenting via `## ` comments.

- Pagination on `GET /api/v1/books` via Spring Data `Page` / `PageRequest`. Query params: `page` (default 1, `@Min(1)`) and `limit` (default 10, `@Min(10) @Max(50)`). Meta: `{total, next_page, prev_page}`; `next_page`/`prev_page` omitted via `@JsonInclude(NON_NULL)` when no neighbour.

Tests use `src/test/resources/application.properties` against `library_test` with `ddl-auto=create-drop`. `BookControllerTest` already calls `bookRepository.deleteAll()` between tests, so no further isolation needed.

Test props share the same import and read `DB_NAME` too — caller passes `DB_NAME=library_test` when running tests (`ddl-auto=create-drop` stays pinned in the test file to keep schema management hermetic).
- Phase 1 of multi-table model: `books` gains `isbn` (NOT NULL, ISBN-10/13 `@Pattern`, immutable after creation), `created_at`, `updated_at`, `deleted_at`. Soft delete via Hibernate `@SQLDelete` (UPDATE deleted_at) + `@SQLRestriction("deleted_at IS NULL")` (every find filters out tombstones). Partial unique index on ISBN (`WHERE deleted_at IS NULL`) declared in `src/main/resources/import.sql` because JPA `@UniqueConstraint` can't express WHERE clauses. DTO split: `WriteRequest` (POST, with `isbn`) vs `UpdateRequest` (PUT, no `isbn`) — immutability enforced by wire-contract construction. `Response` exposes `isbn`/`created_at`/`updated_at`; `deleted_at` stays internal.
- Phase 2 (schema-only): `staffs` table — `id`, `name`, `email`, `password_hash`, `created_at`, `updated_at`, `deleted_at`. Same audit + `@SQLDelete`/`@SQLRestriction` pattern as `books`. Partial unique index on `email` (active rows only) added to `import.sql`. **No repository / service / controller / DTO yet** — entity exists so Hibernate creates the table; CRUD is intentionally out of scope for this phase.
- Phase 3 (schema-only): `members` table — identical column shape to `staffs` (`id`, `name`, `email`, `password_hash`, audit + soft-delete). Partial unique index on `email`. Entity only; no CRUD.
- Phase 4 (schema-only): `book_loans` table — `id`, `book_id` (FK → `books.id`), `member_id` (FK → `members.id`; renamed from the originally proposed `borrower_id` since only members borrow), `borrowed_at`, `returned_at` (nullable — null = still on loan), audit + soft-delete. Implemented as JPA `@ManyToOne(fetch = LAZY)` associations; Hibernate auto-generates the FK constraints. `BookEntity` and `MemberEntity` promoted from package-private to `public` so `loans/` can reference them. Entity only; no CRUD.
- Auth Phase D — RBAC on books + loans endpoints. `BookController` mutations (POST/PUT/PATCH/DELETE) carry `@PreAuthorize("hasRole('STAFF')")`; GETs are open to any authenticated user. New `loans/` feature exposes `POST /api/v1/loans` (borrow) and `PATCH /api/v1/loans/{id}/return`. Caller identity comes from the JWT's `sub` claim via `@AuthenticationPrincipal Jwt jwt`. `LoanService` enforces "only MEMBER can borrow/return" against the **live** DB role (not the JWT claim — claim could be stale), throwing `LoanNotPermittedException` → 403. Other domain errors: `LoanConflictException` → 409 (no copies available, double-return), `LoanNotFoundException` → 404 (also used to mask "loan belongs to another member" so we don't disclose other users' loan ids). `borrow` checks `active < count` before saving; race window is documented in service comments (real fix: pessimistic lock). `SecurityConfig` gains a custom `AuthenticationEntryPoint` (401) and `AccessDeniedHandler` (403) that emit our `ErrorResponse` JSON shape instead of the default empty 401/403. Test split: `BookControllerTest` keeps `addFilters=false` + `@WithMockUser(roles="STAFF")` for the domain assertions; new `BookControllerSecurityTest` runs filters ON + real JWTs to verify the MEMBER↔STAFF boundary. `LoanServiceTest` covers all logic paths with mocks; `LoanControllerTest` exercises the same flows end-to-end with real tokens and asserts `available_count` drops by 1 after a member borrows.
- Broader test coverage on the auth side. `AuthServiceTest` (Mockito unit) covers signup happy-path / duplicate-email, login happy / unknown-email / wrong-password, refresh happy / decoder-rejects / wrong-type / malformed-subject / missing-user, logout no-op — all without booting Spring. `JwtServiceTest` builds a real `NimbusJwtEncoder` + `NimbusJwtDecoder` against a fixed HS256 secret and asserts the issued tokens carry `type` / `role` / `email` / `sub` / `iss` claims and the right TTLs. Uses `ReflectionTestUtils.setField(user, "id", ...)` to seed an id without adding a footgun `setId` to `UserEntity`.
- Auth Phase C — auth endpoints live at `/api/v1/auth/{signup,login,refresh,logout}`. Wire shape mirrors the books `{rootKey:{...}}` envelope: `{"signup":{...}}`, `{"login":{...}}`, `{"refresh":{...}}`, response `{"tokens":{access_token, refresh_token, token_type:"Bearer", expires_in}}`. `AuthService` orchestrates: signup creates a MEMBER-role user (staff is seeded manually), login verifies via `PasswordEncoder.matches`, refresh decodes the incoming token via `JwtDecoder`, checks `type=refresh`, and re-issues; logout is a no-op for now (all-JWT, client discards). New domain exceptions in `auth/`: `EmailAlreadyExistsException` (→ 409), `InvalidCredentialsException` (→ 401, message identical to "wrong password" so callers can't probe email existence), `InvalidTokenException` (→ 401, distinct messages for "invalid/expired" / "not a refresh token" / "user no longer exists"). `UserRepository` gained `findByEmail` (filtered to active rows by `@SQLRestriction`). Tests cover signup happy-path + dup-email + short-password, login (member + staff) + wrong-password + unknown-email, refresh happy + with-access-token + garbage-token, logout 204, and a claim-shape assertion that decodes the issued access token and verifies `role`/`email`/`type`.
- Auth Phase B — Spring Security wired in. `spring-boot-starter-security` + `spring-boot-starter-oauth2-resource-server` (gives `NimbusJwtDecoder`/`NimbusJwtEncoder`) + `spring-security-test`. New `auth/` feature package holds `SecurityConfig` (CSRF off, sessions stateless, `/api/v1/auth/**` + `/error` public, everything else `authenticated()` via `oauth2ResourceServer.jwt()`) and `JwtService` (HS256, issues access + refresh tokens with `iss`/`sub`/`iat`/`exp` + `email`/`role`/`type` claims). `BCryptPasswordEncoder` bean (default strength 10). HS256 secret comes from `JWT_SECRET` (no default — startup fails fast on missing). TTLs default to 15m / 7d, overridable via `JWT_ACCESS_TTL`/`JWT_REFRESH_TTL`. `JwtAuthenticationConverter` maps the JWT `role` claim → `ROLE_<role>` authority so `@PreAuthorize("hasRole('STAFF')")` works in Phase D. `@EnableMethodSecurity` enabled. `BookControllerTest` runs with `@AutoConfigureMockMvc(addFilters = false)` — that test covers the books domain; security itself gets exercised by Phase C/D's own tests that mint real JWTs via `SecurityMockMvcRequestPostProcessors.jwt()`.
- Auth Phase A — merged `staffs` + `members` schemas into a single `users` table with a `role` enum column (`MEMBER` | `STAFF`, stored as `EnumType.STRING`). `UserEntity` lives in a new `users/` feature package alongside `UserRepository` and `UserRole`. `book_loans.member_id` renamed to `user_id`; `BookLoanEntity.member` field → `user`. Email uniqueness collapsed to a single partial index (`users_email_active_uidx`). Driver: identical auth flow for both roles, so doubling the schema would force doubling the auth machinery — the "members can borrow, staff cannot" rule moves to the service layer (Phase D) and Spring Security `@PreAuthorize` (Phase D). Old `staffs/` and `members/` packages deleted.
- Books availability + count/delete guards. Listing/viewing now returns `count` + `available_count` (= `count − active loans`) in a single SQL round trip via `findAllWithAvailability` / `findByIdWithAvailability`: JPQL `LEFT JOIN BookLoanEntity l ON l.book = b AND l.returnedAt IS NULL AND l.deletedAt IS NULL` + constructor projection `SELECT new com.training.library.books.BookView(b, COUNT(l))` + explicit `countQuery` (otherwise Spring Data tries to derive one from the `GROUP BY` and breaks). Service returns `BookView` end-to-end; mapper computes `available_count` in one default method. `UpdateRequest.count` / `PatchRequest.count` tightened to `@Positive` (≤0 → 400 via Bean Validation). Service rejects mutations where `count < active loans` and deletes where active loans exist with new `BookConflictException` (`@RestControllerAdvice` → 409 Conflict). All deletes stay soft (existing `@SQLDelete` on books and loans). `LoanRepository` is the second feature repository — derived query `countByBookIdAndReturnedAtIsNull`. `MemberRepository` added (empty) so integration tests can seed members.

## Deferred gaps (explicit follow-ups)

- **409 Conflict mapping for unique-constraint violations.** Today any duplicate hit on a partial-unique index (active ISBN in `books`, soon active email in `staffs` / `members`) bubbles up as a 500. Map `DataIntegrityViolationException` → 409 in `GlobalExceptionHandler`, ideally with a discriminator that surfaces which field collided. Until that lands, integration tests treat duplicate-active-key as "exception raised", not a specific HTTP status.
- **Partial-index verification tests.** No test today asserts that (a) inserting two active rows with the same `isbn`/`email` is rejected, or (b) inserting one after the prior soft-delete succeeds. The index runs (otherwise tests would have failed schema generation), but we have no positive regression coverage. Add when 409 mapping lands — easier to assert response code than raw exception type.
- **`import.sql` is a temporary scaffold.** Works because of `IF NOT EXISTS` on `ddl-auto=update`, but it's unversioned and bypasses the application's migration story. Replace with Flyway/Liquibase migrations when the schema stabilises (after Phase 4), and flip `ddl-auto` to `validate`.
- **Sorting on list endpoints.** `Pageable` is already wired; just need a `sort` query param on each list endpoint.
- **Password hashing.** `staffs.password_hash` (Phase 2) currently stores the plaintext value under the `_hash` column. Documented at the call site. Replace with `spring-security-crypto` + `BCryptPasswordEncoder` once a real auth flow lands. Migration: hash existing plaintext rows in-place during the deploy that adds the encoder.
